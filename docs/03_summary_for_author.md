# 프로젝트 요약 — 지원자 본인용 (면접 전 다시 읽기)

작성일: 2026-09-10 · 이 문서는 **저장소를 처음 보는 사람이 아니라 지원자 본인**을 위한 것이다.
기술 세부는 `README.md` 와 `docs/agents/*.md` 에 있고, 여기서는 **무슨 일이 있었고 무엇을 말할 수 있는가**만 정리한다.

> ⚠️ **이 문서에서 아직 비어 있는 것**: 아래 §7 "내가 결정한 것 / 에이전트가 한 것" 은 **본인이 직접 써야 한다.**

> 가장 큰 리스크다(Astra 최종 검토 조건). 이건 대필하면 의미가 없다.

## 1. 한 줄

공개 뇌졸중 MRI 데이터(OpenNeuro SOOP, CC0)로 **병변 찾기 → 뇌졸중 원인 분류 → 예후 예측** 세 과제를
끝까지 돌려보고, **안 되는 과제는 왜 안 되는지 밝혀서 되는 문제로 옮긴** 개인 프로젝트.

## 2. 세 과제와 결과

| 과제 | 무엇 | 결과 |
|---|---|---|
| ① 병변 분할 | MRI 에서 뇌경색 부위를 자동으로 칠하기 | **성공** — 사전 등록 기준 4/4 통과 |
| ② 병인(원인) 분류 | 큰혈관/심장/작은혈관/기타 중 무엇이 원인인가 | **실패** — "병변 크기 하나"보다 못함 |
| ③ 예후 예측 | 퇴원할 때 혼자 생활 가능한가 | **성공** — 사전 등록 기준 2/2 통과 |

숫자는 `README.md` 의 결과표 참조. 외울 필요가 있는 것만:
- 분할: **Dice 0.688**, 병변 부피 일치도 **ICC 0.984**, 검출률 **0.977**
- 예후: **AUC 0.799**, 연습(0.821) → 실전 하락폭 **0.02**
- 병인: 주 지표 **판정 불가**

## 3. ②가 실패한 이유 — 면접에서 가장 많이 물어볼 지점

**모델이 나빠서가 아니라 문제가 그렇게 생겼다.**

뇌졸중 원인 중 **SVO(소혈관 폐색)는 의학적 정의 자체가 "병변 1.5 cm 미만"** 이다.
즉 정답 라벨 안에 답(크기)이 들어 있다.

- 병변 크기만 재면 SVO 는 맞는다 (AUC 0.84)
- 크기를 빼면 남는 게 없다 (AUC 0.51 = 찍는 수준)

처음 세운 목표는 "크기 특징 제외 AUC > 0.60" 이었는데, **부피 특징 하나만으로 0.65 가 나왔다.**
즉 **모델 없이도 통과되는 목표**였다. 그래서 목표를 스스로 폐기하고 더 어려운 기준으로 바꿨고,
바꾼 기준에서 떨어졌다. **더 쉬운 원래 기준으로 채점하면 통과한다**(README 에 같이 적어둠).

> **말할 때**: "성능이 안 나왔습니다" 가 아니라
> **"라벨 정의에 답이 들어 있는 과제였고, 그걸 측정으로 확인한 뒤 기준을 바꿨습니다"** 라고 말한다.

## 4. ③으로 옮긴 근거 — 회사 조사

- JLK 는 **진단·병변분할·유형분류를 이미 제품으로 판매** 중이다 (JBS-01K 등).
- **제품 페이지 전체에 "예후"·"mRS" 문구가 0건.** 반면 예후는 **논문**(JKMS 상지운동 예후, JAHA 병변증가-3개월 독립성)과
  회사 문구("급성기 응급실에서 만성기 예후 예측까지")에만 존재한다.
- 채용공고 담당업무에 **"상용화 제품에 대한 연구지원 및 임상적 근거 창출"**.

→ **회사가 제품으로 아직 안 채운 칸이 예후다.** 그래서 그쪽으로 옮겼다.

**전환의 핵심(이게 기술적 포인트)**: `mRS`(퇴원 시 기능 상태)를
- 병인 분류에서는 **"결과 변수라 누수"** 라고 입력에서 **제외**했고,
- 예후 예측에서는 **맞춰야 할 정답(타깃)** 으로 썼다.

**같은 변수라도 역할이 바뀌면 정당성이 바뀐다** — 누수를 이해하고 있다는 증거로 남았다.

## 5. 말할 거리 4개 (우선순위 순)

### (1) 평균 지표가 숨긴 실패를 찾았다 — 가장 강한 카드
평균 Dice 는 0.683 인데, 스캐너별로 쪼개보니 **Siemens 환자 4명 전원이 빈 마스크**를 받았다.
그중 하나는 **107 mL 대형 병변**이라 크기 문제가 아니다.

가설 두 개를 세우고 **실험으로 하나를 죽였다**:
- 가설 A(ADC 채널 부호 반전) → **TRACE 만 쓰는 모델도 똑같이 실패** → 기각
- 가설 B(정규화 포화, Siemens 는 뇌의 10 % 가 클립값) → **백분위 정규화로 재평가하니 Dice 0 → 0.844** → 지지

**요점**: 두 정규화 방식은 **평균 지표로는 구별되지 않는다**(0.6830 vs 0.6804). 실패 모드는 전혀 다르다.
→ *"평균만 보면 제품으로 못 쓸 실패를 놓친다"* 는 이야기. 의료기기 회사에 특히 잘 먹힌다.

### (2) 버그 3개를 감이 아니라 측정으로 잡았다
- **정규화 클립이 병변 신호의 절반을 잘라내고 있었다** (병변 복셀 50.7 %가 잘림) → 고치니 **0.595 → 0.683**
- **ADC 영상 44명분이 통째로 포화**돼 있었다 (분모가 정확히 0 이 되는 케이스를 방어 안 함)
- **좌우 축이 앞뒤로 뒤바뀌어** 있었다 → 편측성 특징이 무의미했고, "좌우 반전" 증강이 실제로는 앞뒤 반전이었다

### (3) 통념을 데이터로 반박했다
"작은 병변은 경계를 못 그려서 점수가 낮다" → **틀렸다.**
- 작은 병변 구간에서 **Dice 0 인 환자들을 빼면 나머지는 중간 크기 구간과 점수가 같다** → 못 그리는 게 아니라 **못 찾는 것**
- 찾은 것들의 **예측/실제 부피 비는 1.00~1.19** → 과소분할이 아니다
- 그래서 그 통념을 전제로 만든 개선책 3개(Tversky 등)가 **실제로 성능을 떨어뜨렸다**

### (4) 내 기준을 내가 폐기했고, 같은 실수를 두 번 하지 않았다
- 병인 과제의 주 지표는 **"참값이 맞아도 40 % 확률로 판정 불가가 나오도록"** 설계돼 있었다(사후에 시뮬레이션으로 확인).
- 예후 과제에서는 **기준을 정하기 전에** 시뮬레이션(2,000 × 2,000)으로
  **판정 불가 확률 0.000** 을 확인하고 걸었다.
- 검정력이 없는 주장(영상 증분)은 **아예 판정 기준에서 뺐다.** 실제로 유의하게 나왔지만
  **"검정력 없다고 선언한 항목을 사후에 주장으로 승격시키지 않는다"** 고 적고 참고치로만 뒀다.

## 6. 정직하게 말해야 할 한계

1. **병인 분류는 실패했다.** 숨기지 않고 README 에 그대로 있다.
2. **외부 데이터 검증을 못 했다.** 다른 기관 데이터(ISLES'22)를 받으려 했으나 이 서버에서 Zenodo 가 차단(504)돼 있었다.
3. **예후 데이터에 선택 편향이 있다.** 퇴원 mRS 기록이 있는 환자는 **중증 쪽에 몰려 있다**
   (병변 15.08 mL·NIHSS 7 vs 결측군 5.31 mL·NIHSS 3). 결과 보기 전에 미리 선언했다.
4. **"테스트셋을 한 번도 안 봤다" 고 말할 수 없다.** 외부 검증 에이전트(Codex/GPT-6)가
   "인덱스를 만들려면 전 코호트 마스크를 읽어야 하므로 그 문구는 거짓" 이라고 지적했고, 문구를 정확하게 고쳤다.
   → 정확한 표현은 **"결과 라벨에 한해 blind 인 내부 홀드아웃"**.
5. **퇴원 mRS 는 국제 표준인 90일 mRS 가 아니다.** 선행연구 수치와 직접 비교하지 않는다.
6. **Siemens 발견은 n=3 이고 사후 분석이다.** 확정이 아니라 향후 과제로 기록했다.
7. **구조적 갭**(공고 자격요건 대비): 학회·학술지 publication 은 개인 프로젝트로 대체 불가.
