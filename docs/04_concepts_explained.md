# 1부. 의학 배경 — 최소한만

## 1.1 뇌졸중(stroke)은 두 종류다

| 종류 | 무슨 일 | 비율 |
|---|---|---|
| **허혈성(ischemic)** — 뇌경색 | 혈관이 **막혀서** 뇌에 피가 안 간다 | 약 80 % |
| **출혈성(hemorrhagic)** — 뇌출혈 | 혈관이 **터져서** 피가 샌다 | 약 20 % |

**이 프로젝트는 허혈성(뇌경색)만 다룬다.** JLK 제품군에는 둘 다 있다(JLK-ICH 가 출혈용).

## 1.2 왜 MRI 의 DWI 를 쓰나

뇌경색이 생기면 세포가 부어오르면서 **물 분자의 움직임(확산, diffusion)이 제한**된다.
이걸 잡아내는 게 **DWI(Diffusion Weighted Imaging, 확산강조영상)** 다.

- **급성기(발병 수 시간~며칠) 뇌경색을 가장 빨리, 가장 뚜렷하게 보여준다.** CT 로는 초기에 잘 안 보인다.
- 그래서 "골든타임" 이 중요한 뇌졸중에서 DWI 가 표준이다.

이 프로젝트가 쓰는 영상 2종:

| 이름 | 정체 | 병변에서 어떻게 보이나 |
|---|---|---|
| **TRACE (b1000)** | 확산강조 원본 | 병변이 **밝게(고신호)** 보인다 |
| **ADC** | 확산계수 지도 (계산해서 만든 영상) | 병변이 **어둡게(저신호)** 보인다 |

**둘을 같이 쓰는 이유**: TRACE 만 보면 **T2 shine-through** 라는 착시가 있다 —
오래된 병변도 밝게 보일 수 있다. **ADC 가 같이 낮아야 진짜 급성기**다.
그래서 모델 입력을 **2채널(TRACE + ADC)** 로 했다.

> 💡 이 점이 나중에 **Siemens 실패**와 연결된다. 그 환자들은 병변부 ADC 가 오히려 **높게** 들어와 있었다.

## 1.3 TOAST 분류 — 뇌경색의 "원인"

같은 뇌경색이라도 원인이 다르고, 원인에 따라 치료(약)가 달라진다. 국제 표준 분류가 **TOAST** 다.

| 약자 | 한글 | 무슨 뜻 | 병변 특징 |
|---|---|---|---|
| **LAA** | 큰동맥 죽상경화 | 목·뇌의 **큰 혈관**이 좁아지거나 막힘 | 보통 크다 |
| **CE** | 심장탓 색전 | **심장**에서 생긴 혈전이 날아가 막음 (심방세동 등) | 크고, 여러 곳일 수 있다 |
| **SVO** | 소혈관 폐색 (열공경색) | 뇌 깊숙한 **작은 혈관**이 막힘 | **정의상 1.5 cm 미만** |
| **Others / Cryptogenic** | 기타 / 원인불명 | 드문 원인 / 끝내 못 밝힘 | — |

> 🔴 **이 프로젝트에서 가장 중요한 한 줄**:
> **SVO 는 의학적 정의 자체가 "병변이 1.5 cm 미만"** 이다.
> 즉 **정답 라벨 안에 "크기" 라는 답이 들어 있다.** 뒤의 4.2 에서 자세히.

## 1.4 임상 지표 두 개

**NIHSS** (National Institutes of Health Stroke Scale)
- 뇌졸중 **중증도** 점수. 0~42점, 높을수록 심각.
- 의식·시야·팔다리 마비·언어 등을 항목별로 채점해서 합산.
- **입원 시점**에 잰다 → 예측 모델의 **입력**으로 쓸 수 있다.

**mRS** (modified Rankin Scale)
- 뇌졸중 후 **기능 상태(얼마나 혼자 사는가)**. 0~6점.
- 0 = 증상 없음 … 3 = 도움이 좀 필요 … 5 = 침상 생활 … **6 = 사망**
- 국제 관례로 **0–2 = "양호(독립적 생활 가능)"**, **3–6 = "불량"** 으로 나눈다.
- **퇴원 시점 또는 90일 후**에 잰다 → **결과(outcome)** 다.

> 🔴 **두 번째로 중요한 한 줄**:
> mRS 는 **결과**이므로, 원인(병인)을 맞히는 모델의 **입력으로 쓰면 반칙(누수)** 이다.
> 그런데 **예후 예측 모델에서는 그게 맞춰야 할 정답(타깃)** 이 된다.
> **같은 변수인데 역할이 바뀌면 정당성이 바뀐다.** 뒤의 4.5 에서 자세히.

# 2부. 지표 읽는 법 — 숫자가 무슨 뜻인지

## 2.1 Dice 계수 — "얼마나 잘 칠했나"

병변 분할은 **픽셀마다 병변/아님을 칠하는 일**이다. 정답과 얼마나 겹치는지를 재는 게 Dice.

```
Dice = 2 × (겹친 부분) / (내가 칠한 것 + 정답)
```

- **1.0** = 완벽히 일치, **0** = 하나도 안 겹침
- 0.5 는 "절반쯤 맞음"이 **아니다.** 겹침을 두 번 세고 분모로 나누는 구조라, 체감보다 짜다.

**이 프로젝트 결과**: test **0.688**

| 맥락 | Dice |
|---|---|
| 이 프로젝트 (2D U-Net, 128×128) | **0.688** |
| 공개 벤치마크 nnU-Net (3D, 대형) | ~0.81 |
| 참고: JLK 보도자료의 판독의+AI | 0.742 ← ⚠️ **이건 모델 단독 성능이 아니다** |

> ⚠️ **면접에서 절대 하면 안 되는 비교**: JLK 보도자료의 "DSC 0.523 → 0.742" 는
> **의사 혼자 vs 의사+AI** 의 수치다(reader study). 모델 단독 Dice 와 같은 축에 놓으면 바로 지적당한다.
> Astra 가 이걸 반박해서 README 에서 비교표를 아예 안 만들었다.

## 2.2 병변 크기별로 쪼개 보는 이유

전체 평균 0.688 인데 쪼개보면:

| 병변 크기 | Dice | 몇 명 |
|---|---|---|
| < 2 mL (작음) | **0.552** | 60 |
| 2–10 mL | 0.689 | 57 |
| 10–50 mL | 0.707 | 60 |
| ≥ 50 mL (큼) | **0.857** | 41 |

**작은 병변이 훨씬 어렵다.** 그리고 작은 병변이 바로 **SVO(열공경색)** 구간이다.
평균만 보고하면 이 사실이 숨는다 → **그래서 크기별로 따로 보고하는 걸 의무로 정했다.**

## 2.3 민감도 / 특이도 — 그리고 왜 여기선 특이도를 못 구하나

|  | 정답: 병변 있음 | 정답: 병변 없음 |
|---|---|---|
| **모델: 있다** | TP (맞게 찾음) | FP (헛것 봄) |
| **모델: 없다** | FN (놓침) | TN (맞게 없다 함) |

- **민감도(sensitivity)** = TP / (TP+FN) — **있는 걸 얼마나 안 놓치나**
- **특이도(specificity)** = TN / (TN+FP) — **없는 걸 얼마나 안 헛보나**

**이 프로젝트 민감도: 0.977** (218명 중 213명에서 병변을 찾음)

> 🔴 **특이도는 계산이 불가능하다.** 데이터셋에 **병변 없는 환자가 0명**이기 때문이다.
> 마스크가 있는 1,451명은 **전원 병변 양성**이다. 분모(TN+FP)가 0 이라 나눌 수가 없다.
> A1 이 "민감도·특이도를 보고해야 한다"고 했을 때 **Astra 가 "이 데이터로는 정의가 안 선다"고 반박**했고,
> A2 가 독립적으로 재확인했다(`acuteischaemicstroke` 열의 관측값이 전부 1, 0 이 하나도 없음).
> → 코드에서 특이도는 `NaN` 으로 출력된다. **"보고를 생략" 한 게 아니라 "계산 불가"** 다. 이 구분이 중요하다.

## 2.4 ICC — "부피를 얼마나 정확히 재나"

병변을 칠하는 것과 별개로, **병변 부피(mL)를 정확히 재는 것**이 임상적으로 중요하다
(JLK-DWI 제품의 핵심 출력이 부피 측정이다).

**ICC(2,1)** = Intraclass Correlation Coefficient. 두 측정값(모델 vs 정답)이 **절대값까지 일치**하는 정도.
- 상관계수(correlation)와 다르다. 상관은 "비례하면" 1 이지만, ICC 는 **값 자체가 같아야** 1 이다.
  (모델이 항상 정답의 2배로 재면 상관은 1.0, ICC 는 낮다)
- 해석 기준(Koo & Li 2016): < 0.5 나쁨 / 0.5–0.75 보통 / **0.75–0.90 좋음** / > 0.90 매우 좋음

**이 프로젝트: test ICC 0.984** ← 이게 사실 분할에서 가장 잘 나온 수치다.

## 2.5 Bland-Altman — 부피 오차를 보는 또 다른 방법

"평균적으로 얼마나 틀리나" 가 아니라 **"얼마나 흔들리나"** 를 본다.
- **bias(편향)**: 평균적으로 과대/과소 추정하는 정도. 이 프로젝트 **−0.74 mL** (거의 없음)
- **LoA(일치 한계)**: 95 % 의 오차가 들어가는 범위. 이 프로젝트 **[−22.0, +20.5] mL**

> 읽는 법: "평균은 거의 안 틀리는데, 개별 환자로는 ±20 mL 까지 벌어질 수 있다."
> 평균만 보면 안 되는 이유다.

## 2.6 AUC — 분류 성능

**AUC(ROC 곡선 아래 면적)**: 0.5 = 동전 던지기, 1.0 = 완벽.

**직관적 해석**: **"불량 환자 한 명과 양호 환자 한 명을 무작위로 뽑았을 때,
모델이 불량 환자에게 더 높은 점수를 줄 확률"**

| AUC | 통상 해석 |
|---|---|
| 0.5 | 무의미 |
| 0.7–0.8 | 쓸 만함 (acceptable) |
| 0.8–0.9 | 좋음 (excellent) |
| > 0.9 | 뛰어남 |

**이 프로젝트 예후 예측: 0.799** ← "쓸 만함"의 위쪽

**macro OvR AUC**: 클래스가 3개 이상일 때, 각 클래스를 "나 vs 나머지(One-vs-Rest)"로 보고
AUC 를 구한 뒤 **평균** 낸 값. 병인 분류(4클래스)에서 쓴 게 이거다.

## 2.7 캘리브레이션 — "70 % 라고 말하면 정말 70 % 인가"

AUC 는 **순위**만 본다. 하지만 실제로 쓰려면 **확률 자체가 맞아야** 한다.

- **Brier score**: 예측 확률과 실제의 제곱오차 평균. 낮을수록 좋다. (이 프로젝트 **0.180**)
- **Brier skill**: 그냥 평균 유병률로 찍는 것보다 얼마나 나은가. (이 프로젝트 **0.245** = 24.5 % 개선)
- **캘리브레이션 기울기**: 1.0 이 이상적. 1 보다 작으면 **과신**(극단적 확률을 너무 자주 말함).
  (이 프로젝트 **0.829** — 약간 과신하지만 양호한 편)

# 3부. 실험 설계 개념 — 이게 이 프로젝트의 진짜 내용

## 3.1 Train / Validation / Test — 왜 셋으로 나누나

| 이름 | 한글 | 역할 | 몇 번 보나 |
|---|---|---|---|
| **train** | 학습 | 모델이 직접 배우는 데이터 | 계속 |
| **val** | 검증 | 어떤 모델·설정이 나은지 **고르는** 데 씀 | 계속 |
| **test** | 시험 | **최종 성적표**. 고르는 데 쓰면 안 됨 | **딱 한 번** |

**왜 test 를 한 번만 보나?**
test 를 보고 모델을 고치면, 그 순간 test 는 더 이상 "본 적 없는 데이터"가 아니다.
여러 번 보면서 제일 좋은 걸 고르면 **"운 좋은 값"을 성적표로 쓰게 된다.**

이 프로젝트 split: **train 1,015 / val 218 / test 218**

## 3.2 환자 단위 split — 이걸 틀리면 다 무너진다

MRI 한 명당 슬라이스(단면)가 25장쯤 나온다. 1,451명 × 25장 ≈ 36,000장.

**❌ 잘못된 방법**: 36,000장을 섞어서 8:1:1 로 나눈다
→ **같은 환자의 1번 슬라이스는 train, 2번 슬라이스는 test** 에 들어간다
→ 모델이 그 환자의 뇌 모양을 이미 외웠으므로 **점수가 뻥튀기된다**

**✅ 올바른 방법**: **환자를 먼저 나누고**, 그 환자의 슬라이스는 전부 같은 쪽으로 보낸다

이 프로젝트는 `CLAUDE.md` 에 **"슬라이스 단위 split 금지"** 를 규칙으로 박아놨고,
`diagnose.py` 가 매번 **train/val/test 교집합이 0인지 검사**한다.

## 3.3 데이터 누수(leakage) — 여러 얼굴이 있다

**누수 = 모델이 실제 상황에서는 알 수 없는 정보를 훔쳐보는 것.** 이 프로젝트에서 나온 종류:

| 종류 | 이 프로젝트의 사례 | 어떻게 처리했나 |
|---|---|---|
| **환자 단위 누수** | 같은 환자 슬라이스가 train/test 에 나뉘는 것 | 환자 단위 split 강제 |
| **결과 변수 누수** | mRS(퇴원 상태)로 병인을 맞히기 | 병인 입력에서 제외 |
| **정규화 누수** | test 포함 전체 평균으로 밝기 보정 | **환자별 자기 통계만** 사용 (구조적으로 불가능하게) |
| **라벨 정의 누수** | **SVO = "1.5 cm 미만"** | ← **못 막았다.** 4.2 참조 |
| **모델 선택 누수** | test 로 최고 모델 고르기 | test 1회 원칙 |
| **프로토콜 누수** | 장비·자장세기로 라벨 맞히기 | 입력에서 제외 (검증: 단독 AUC 0.49 = 무의미) |

> 💡 **라벨 정의 누수가 가장 악질**이다. 코드로 막을 수 없기 때문이다. 데이터를 이해해야만 보인다.

## 3.4 사전 등록(pre-registration) — 이 프로젝트의 핵심 방법론

**뜻**: **결과를 보기 전에** "무엇을 성공으로 볼지"를 문서에 못 박는 것.

**왜 필요한가**: 결과를 본 뒤에 기준을 정하면, 사람은 무의식적으로 **잘 나온 쪽에 맞춰 기준을 고른다.**
- 예: 지표 10개를 재고 그중 잘 나온 3개만 보고하기
- 예: "AUC 0.60 넘기"라고 했다가 0.58 나오니 "0.55 면 충분하다"고 바꾸기

이 프로젝트는 `docs/00_project_charter.md` 에 기준을 먼저 쓰고, **test 를 연 뒤에는 고치지 않았다.**
기준을 바꾼 적이 한 번 있는데(v1 → v2), **그것도 test 를 열기 전**이었고 **바꾼 이유와 원래 문구를 표로 남겼다.**

## 3.5 통계적 검정력(power) — E1 이 실패한 진짜 이유

**뜻**: **실제로 효과가 있을 때, 그걸 찾아낼 확률.**

표본이 적으면 진짜 효과가 있어도 "모르겠다"가 나온다. 이걸 **검정력이 낮다**고 한다.

**이 프로젝트의 실제 사례 — 병인 분류 E1**:
- 기준: "LAA vs CE 구분 AUC > 0.55, 단 신뢰구간 하한이 0.5 를 넘어야 통과"
- test 표본: LAA 35명 + CE 22명 = **57명**
- 나중에 시뮬레이션해보니 → **참값이 맞아도 40 % 확률로 "판정 불가"가 나오는 기준**이었다

즉 **이길 수 없는 게임을 설계해놓고 진 것**이다. 이건 모델 문제가 아니라 **설계 문제**다.

**그래서 예후 과제에서는 반대로 했다**:
- 기준을 정하기 **전에** 시뮬레이션(2,000 × 2,000회)을 돌려
- **판정 불가 확률 = 0.000** 을 확인하고 걸었다
- 그리고 **검정력이 없는 주장(영상 증분)은 아예 기준에서 뺐다**

> 🔴 이게 면접에서 제일 잘 먹힐 대목이다.
> **"실패에서 배운 걸 다음 설계에 반영했다"** 는 구체적 증거이기 때문이다.

## 3.6 신뢰구간(CI)과 부트스트랩

**신뢰구간**: "이 숫자가 얼마나 흔들릴 수 있나"의 범위.
- AUC 0.799 **[0.698, 0.889]** = "82명으로 쟀더니 0.799 인데, 진짜 값은 0.70~0.89 어딘가"

**부트스트랩**: 신뢰구간을 구하는 방법.
가진 데이터에서 **복원추출로 가짜 표본을 수천 번 만들어** 매번 지표를 계산하고, 그 분포의 2.5 %~97.5 % 를 자른다.

> 💡 **중요**: 이 프로젝트는 **환자 단위로** 복원추출한다. 픽셀 단위로 하면 구간이 가짜로 좁아진다.

**왜 이게 중요했나**: 병인 분류에서 증분이 **+0.035** 로 양수였지만
신뢰구간이 **[−0.039, +0.108]** 로 **0 을 포함**했다 → "있다고 말할 수 없다."
점추정만 보고 "개선됐다"고 했으면 과장이었을 것이고, 실제로 A1 이 그 누락을 잡아냈다.

## 3.7 중첩 교차검증(nested CV) — 낙관 편향 막기

**일반 교차검증(CV)**: 데이터를 5조각 내고, 4조각으로 학습 → 1조각으로 평가. 5번 반복해서 평균.

**문제**: 후보 모델 28개를 CV 로 재고 **그중 제일 높은 걸 고르면**, 그 값은 **낙관적**이다.
(28번 주사위를 굴리고 제일 큰 눈을 "내 실력"이라고 하는 셈)

**중첩 CV**: 바깥 루프는 **평가만**, 안쪽 루프에서 **모델을 고른다.**
고르는 과정 자체를 평가에 포함시켜서 낙관을 제거한다.

**이 프로젝트 실측**: 일반 CV 최고값 **0.827** vs 중첩 CV **0.821**
→ 정직한 값은 0.821 이고, **사전 등록의 기준점으로 0.821 을 썼다.**

## 3.8 재현성(reproducibility)

**같은 코드 + 같은 seed = 같은 결과**여야 한다. 안 그러면 실험 비교가 무의미하다.

**이 프로젝트가 한 것**:
- 모든 난수를 `seed_everything(2026)` 으로 고정
- split 파일의 **sha256 해시**를 헌장에 적어두고 매번 대조
- **물리적으로 다른 GPU 2장에서 40 epoch 학습을 2번 돌려 `best.pt` 가 바이트 단위로 동일**한 것을 확인

> 이건 자랑해도 되는 부분이다. 대부분의 프로젝트가 여기까지 안 한다.

## 4.1 왜 2D U-Net 인가? 3D 가 더 좋지 않나?

**U-Net**: 영상 분할의 표준 구조. 이름 그대로 **U 자 모양**이다.
- **왼쪽(수축 경로)**: 영상을 점점 줄이면서 "무엇이 있는지" 파악
- **오른쪽(확장 경로)**: 다시 키우면서 "어디에 있는지" 복원
- **가로 연결(skip connection)**: 줄이기 전의 세밀한 정보를 건너뛰어 전달 → 경계가 뭉개지지 않음

**왜 3D 가 아니라 2D 인가** (답변용):
> 이 데이터는 **슬라이스 두께가 5 mm** 라 z축 해상도가 매우 낮습니다(평면은 1 mm 이하).
> 3D 컨볼루션의 이점은 z축 연속성인데, 5 mm 간격이면 그 이점이 작습니다.
> 실제로 **2.5D(인접 3슬라이스 채널 스택)를 실험했지만 소병변 Dice 차이가 +0.004 로 잡음 수준**이었습니다.
> 개인 프로젝트 범위와 "끝까지 돌려본다"는 목표를 고려해 2D 로 고정하고, 그 판단 근거를 문서에 남겼습니다.

## 4.2 🔴 왜 병인 분류가 실패했나 — 가장 중요한 질문

**답변 뼈대**:
> 모델 문제가 아니라 **라벨 정의의 문제**였습니다.
> TOAST 분류에서 **SVO 는 정의 자체가 "병변 1.5 cm 미만"** 입니다. 즉 라벨 안에 크기가 들어 있습니다.
>
> 이걸 측정으로 확인했습니다:
> - **병변 부피 단 하나의 특징**으로 4클래스 macro AUC 가 **0.65** 가 나옵니다.
> - SVO 만 빼면 그 값이 **0.51**, 즉 **동전 던지기 수준**으로 떨어집니다.
> - 즉 "분류가 되는 것처럼 보이던" 신호는 거의 전부 **SVO 의 크기 정의**에서 왔습니다.
>
> 원래 성공 기준이 "크기 특징을 제외한 AUC > 0.60" 이었는데, **부피 하나로 0.65 가 나오니
> 모델 없이도 통과되는 기준**이었습니다. 그래서 기준을 폐기하고,
> **크기 지름길이 가장 약한 축인 LAA vs CE 구분**을 주 지표로 바꿨습니다.
> 그리고 거기서 **판정 불가**로 끝났습니다.
>
> 덧붙이면, "크기 제외 세트"라고 불렀던 특징들도 실제로는 크기와 상관이 있었습니다 —
> 병변 개수(ρ=0.44), NIHSS(ρ=0.47) 가 전부 부피의 대리변수였습니다.
> **이름만 '크기 제외'였지 크기가 빠지지 않았던 겁니다.**

**꼬리 질문 대비**: "그럼 어떻게 했어야 하나?"
> 영상만으로 TOAST 를 맞히는 건 회사 논문에서도 AUC 0.7~0.9 수준으로 어렵습니다.
> 실제 임상에서는 **심전도(심방세동)·경동맥 초음파·혈액검사**를 같이 봅니다.
> 이 데이터에는 그런 변수가 없어서, **영상+기본 임상변수만으로는 한계가 구조적**입니다.

## 4.3 🔴 왜 특정 장비(Siemens)에서 완전히 실패했나

**답변 뼈대**:
> 평균 Dice 는 0.683 인데, **스캐너 제조사별로 쪼개보니 Siemens 환자 4명 전원이 빈 마스크**를 받았습니다.
> 그중 하나는 **107 mL 짜리 큰 병변**이라 크기 문제가 아니었습니다.
>
> 가설을 두 개 세웠습니다:
> 1. **ADC 채널 부호 반전** — Siemens ADC 는 정확히 65,535(=2¹⁶−1)에서 잘려 있고,
>    병변부 ADC 값이 다른 장비와 **부호가 반대**였습니다. 급성 경색은 ADC 가 낮아야 하는데 높게 들어왔죠.
> 2. **정규화 포화** — Siemens 는 밝기 분포가 달라서, 정규화 후 **뇌의 10 % 가 클립값**이 됐습니다.
>
> **검증**: ADC 를 아예 안 쓰는 TRACE-only 모델로 재평가했더니 **똑같이 실패**했습니다
> → **가설 1 기각**.
> 백분위 기반 정규화로 바꿔 재평가했더니 **107 mL 병변이 Dice 0 → 0.844 로 복구**됐습니다
> → **가설 2 지지**.
>
> 핵심은, **두 정규화 방식이 전체 평균으로는 구별되지 않는다**는 겁니다(0.6830 vs 0.6804).
> 평균이 같아도 **실패 모드는 전혀 다릅니다.** 의료기기라면 이런 실패가 치명적이라고 생각합니다.

**꼬리 질문 대비**: "왜 학습이 안 됐나?"
> 학습 데이터 1,015명 중 **Siemens 가 4명**뿐이었습니다. 사실상 못 배운 겁니다.
> 다만 n=3 의 사후 분석이라 확정은 아니고, **향후 과제로 기록**했습니다.

## 4.4 🔴 왜 소병변이 어려운가 — 통념과 다른 답

**답변 뼈대**:
> 흔히 "작으면 경계를 못 그려서 점수가 낮다"고 생각하는데, **뜯어보니 아니었습니다.**
>
> - 작은 병변 구간에서 **Dice 가 정확히 0 인 환자가 시드마다 8~10명** 있고,
>   **그들을 빼면 나머지는 중간 크기 구간과 점수가 같습니다**(0.62~0.65).
> - 찾아낸 병변들의 **예측 부피 / 실제 부피 비가 1.00~1.19** 로, **과소분할이 아닙니다.**
>
> 즉 **"못 그리는" 게 아니라 "아예 못 찾는" 문제**였습니다.
>
> 그래서 "과소분할이니 놓친 것(FN)에 벌점을 더 주자"는 접근(Tversky loss)을 시도했더니
> **오히려 성능이 떨어졌습니다**(−0.028). 전제가 틀렸으니 당연한 결과였고,
> 예측 부피만 1.3~1.5배로 부풀었습니다.
>
> 실제로 효과가 있었던 건 **작은 병변 환자의 슬라이스를 더 자주 뽑는 것**이었습니다.
> 작은 병변은 슬라이스가 1~2장뿐이라 학습에서 과소대표되거든요.
> **못 찾던 환자가 7명 → 4명으로 줄었고**, 찾은 것들의 Dice 는 그대로였습니다.

**정직하게 덧붙일 것**:
> 다만 이 개선안은 **사전에 정한 통과 기준(3시드, 2 SD)을 넘지 못했습니다**(1.75 SD).
> 시드를 5개로 늘리면 넘는데, 그건 사후 분석이라 **"승자"가 아니라 "후보"로 보고**했습니다.

## 4.5 🔴 왜 예후 예측으로 주제를 옮겼나

**답변 뼈대**:
> 성능이 안 나온 걸 붙잡고 튜닝하는 대신, **회사가 실제로 무엇을 하는지 다시 조사**했습니다.

> - JLK 는 **진단·병변분할·유형분류를 이미 제품으로 판매**하고 있습니다(JBS-01K 등).
> - 그런데 **제품 페이지 전체에 "예후" 나 "mRS" 라는 단어가 한 번도 안 나옵니다.**

> 즉 **회사가 제품으로 아직 안 채운 칸이 예후**라고 판단했고, 그쪽으로 옮겼습니다.
>

> 예후 예측에서는 그게 맞춰야 할 정답이 된다**는 겁니다.
> **같은 변수라도 역할이 바뀌면 정당성이 바뀝니다.**

**결과**:
> AUC **0.799**, 연습(0.821)에서 실전으로 **0.02 밖에 안 떨어졌습니다.**
> 임상변수만 쓴 기준선(0.697)보다 **영상을 더했을 때 +0.10** 높았습니다.

## 4.6 왜 40 epoch 인가? 더 돌리면 좋지 않나

**답변 뼈대**:
> 더 돌리면 **Dice 는 올라가는데 부피 정확도(ICC)가 떨어집니다.**
>
> | epoch | val Dice | 부피 ICC |
> |---|---|---|
> | 40 | 0.685 | **0.914** |
> | 60 | 0.694 | 0.866 |
> | 100 | 0.695 | 0.857 |
> | 150 | 0.694 | 0.828 |
>
> Dice 이득은 **+0.010 으로 시드 잡음(±0.007)의 1.4배** 수준인데,
> ICC 는 0.914 → 0.866 으로 크게 떨어집니다.
> 사전 등록 기준이 **ICC ≥ 0.85** 였고, 60 epoch 의 0.866 은 여유가 0.016 뿐인데
> ICC 의 시드 변동이 ±0.05 라 **test 에서 기준을 놓칠 위험**이 컸습니다.
> **Dice 를 양보하고 ICC 여유를 택했습니다.**

## 4.7 왜 정규화 클립을 6 → 10 으로 바꿨나

**배경 개념 — 정규화(normalization)**:
MRI 는 **절대 밝기값에 의미가 없다.** 같은 장비라도 촬영마다 스케일이 다르다.
그래서 환자마다 **"중앙값을 0, 퍼짐을 1"로 맞추는** 작업이 필요하다.

- **z-score**: (값 − 평균) / 표준편차
- **robust z-score**: 평균·표준편차 대신 **중앙값·MAD** 를 쓴다. 이상치에 덜 흔들린다.
- **클립(clip)**: 정규화 후 너무 극단적인 값을 ±N 으로 잘라낸다. 학습 안정화 목적.

**무슨 일이 있었나**:
> 클립이 ±6 으로 설정돼 있었는데, **급성 병변의 TRACE 값 중앙값이 z=+6.24** 였습니다.
> 즉 **병변 복셀의 50.7 %가 클립에 잘려나가고 있었습니다**(정상 뇌는 1.9 %).
> **모델이 봐야 할 신호의 절반이 평평하게 뭉개진 채 학습되고 있던 겁니다.**
>
> 클립을 10 으로 올리니 **val Dice 가 0.595 → 0.683** 으로 올랐습니다.
> 시드 잡음(±0.007)의 **12배** 차이라 명백한 개선이었습니다.

**또 하나의 버그(같이 말하면 좋음)**:
> 그 과정에서 **MAD 가 정확히 0 이 되는 케이스**를 방어하지 않은 버그도 찾았습니다.
> SOOP 의 ADC 영상은 뇌 영역의 절반 이상이 **단일 채움값**이라 MAD 가 0 이 되고,
> 0 으로 나누는 걸 막으려고 더한 작은 값(1e-6) 때문에 **ADC 채널 전체가 포화**됐습니다.
> **1,233명 중 44명(3.6 %)** 이 해당했고, 최악은 복셀의 64 % 가 클립값이었습니다.

| 이 프로젝트가 뭐죠? | 공개 뇌졸중 MRI 로 **병변 분할 → 원인 분류 → 예후 예측** 3단을 끝까지 돌려보고, 안 되는 건 왜 안 되는지 밝힌 개인 프로젝트입니다. |

| 병인 분류는 왜 실패? | **라벨 정의에 답이 들어 있었습니다.** SVO 가 정의상 1.5 cm 미만이라, 부피 하나로 AUC 0.65 가 나옵니다. (4.2) |
| 실패했는데 왜 올렸나요? | **사전에 성공 기준을 정해두고 결과를 그대로 보고하는 게 원칙**이었습니다. 미달했다고 기준을 바꾸면 그 기준이 의미가 없어집니다. |
| 특이도는 왜 없죠? | **이 데이터로는 계산 자체가 불가능**합니다. 병변 없는 환자가 0명이라 분모가 0입니다. (2.3) |
| 테스트셋은 안 봤나요? | **정확히는 "결과 라벨에 한해 blind"** 입니다. 층화 split 을 만들려면 전 코호트 마스크를 읽어야 해서요. 외부 검증에서 지적받아 표현을 고쳤습니다. |
| 왜 3D 를 안 썼나요? | 슬라이스 두께 5 mm 라 z축 이점이 작고, **2.5D 실험도 효과가 잡음 수준**이었습니다. (4.1) |
| AI(에이전트)가 다 한 거 아닌가요? | **측정과 검증은 맡기고, 무엇을 목표로 삼고 무엇을 포기할지는 제가 정했습니다.** 특히 성공 기준 폐기, 주제 전환, Dice 대신 ICC 를 택한 판단이 그렇습니다. ← **본인 말로 다듬을 것** |
| 다음엔 뭘 하고 싶나요? | **외부 기관 데이터 검증**입니다. 이번에 Siemens 실패를 발견했는데, 다기관 데이터가 있어야 제대로 검증됩니다. |

# 6부. 용어 사전 (가나다순)

| 용어 | 뜻 |
|---|---|
| **ADC** | 확산계수 지도. 급성 병변에서 **낮게** 나온다 |
| **AUC** | 분류 성능 지표. 0.5=무의미, 1.0=완벽 |
| **Bland-Altman** | 두 측정값의 차이를 보는 그림. bias 와 LoA 를 본다 |
| **Brier score** | 예측 확률이 실제와 얼마나 맞는지. 낮을수록 좋음 |
| **CE** | 심장탓 색전. TOAST 분류 중 하나 |
| **Dice** | 분할 성능. 겹침 정도. 1.0=완벽 |
| **DWI** | 확산강조영상. 급성 뇌경색을 가장 잘 본다 |
| **ICC** | 급내상관계수. 두 측정값의 **절대적** 일치도 |
| **LAA** | 큰동맥 죽상경화. TOAST 분류 중 하나 |
| **mRS** | 뇌졸중 후 기능 상태 0~6. 0–2 양호 / 3–6 불량 |
| **NIHSS** | 뇌졸중 중증도 점수 0~42 |
| **SVO** | 소혈관 폐색(열공경색). **정의상 1.5 cm 미만** |
| **TOAST** | 뇌경색 원인 분류 체계 (LAA/CE/SVO/기타) |
| **TRACE** | 확산강조 원본 영상. 급성 병변에서 **밝게** 나온다 |
| **U-Net** | 영상 분할용 신경망 구조. U 자 모양 |
| **검정력(power)** | 진짜 효과가 있을 때 그걸 찾아낼 확률 |
| **누수(leakage)** | 모델이 실제로는 알 수 없는 정보를 훔쳐보는 것 |
| **부트스트랩** | 복원추출을 반복해 신뢰구간을 구하는 방법 |
| **사전 등록** | 결과를 보기 전에 성공 기준을 문서로 못 박는 것 |
| **중첩 CV** | 모델 선택 과정까지 평가에 포함시켜 낙관 편향을 제거하는 교차검증 |
| **캘리브레이션** | 모델이 말한 확률이 실제 빈도와 맞는 정도 |
| **클립(clip)** | 정규화 후 극단값을 잘라내는 것 |
