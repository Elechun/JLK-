## 1. 결론 (5줄 요약)

1. **주제 적합성: 매우 높음(확인).** JLK 의 대표 제품 **JBS-01K 는 DWI 기반 뇌경색 병변 분할 + 뇌졸중 유형(TOAST) 분류**이며, 본 프로젝트(SOOP/ds004889, DWI 분할 + 병인 분류)와 과제 구조가 1:1 로 대응한다.
2. **공고 원문은 확보 실패(잡코리아·김박사넷·회사 careers·rndjob 모두 프록시 차단).** 다만 검색 메타데이터로 "인공지능(AI) 빅데이터 연구원(전문연구요원), 석사 이상, 경력무관, 서울 강남구, 병역특례" 는 확인.
3. 다른 JLK 공고에서 확인된 자격요건은 **DL/ML/CV/의료영상 전공·학위 + 해당 분야 학회/학술지 publication + Python 또는 C/C++**, 우대는 **의료영상 top-tier publication / AI 의료 유경험 / EMR·PACS 경험**.
4. **가장 큰 갭 3가지: (P0) DICOM 입출력, (P0) 3D(또는 2.5D) 모델, (P0) 민감도·특이도 등 임상 성능지표 보고.** 현재 프로젝트는 NIfTI·2D U-Net·Dice 중심이라 제품 스펙과 어긋난다.
5. 포지셔닝은 "JLK 문제를 푼다"가 아니라 **"JBS-01K 와 동일한 과제 구조를 공개 데이터로 처음부터 끝까지 직접 돌려본 사람"** 으로 잡는 것이 정확하고 방어 가능하다.

### 갭 우선순위와 권장 조치

**P0 — 반드시 넣을 것 (비용 대비 효과 최고)**
1. **DICOM 처리 최소 1회 경유.** NIfTI 원본을 pydicom 으로 DICOM 시리즈 write → 다시 read → 전처리 파이프라인 투입하는 짧은 경로를 만든다. "DICOM 을 다뤄봤다"는 진술이 사실이 된다.
2. **2.5D 또는 얕은 3D 변형 1개 추가.** 인접 슬라이스 스택(2.5D) 만으로도 "3D 문맥을 고려했다"가 성립하고, 2D 대비 성능 비교표가 그대로 실험 설계 능력의 증거가 된다.
3. **평가지표에 민감도·특이도·환자 단위 검출률 추가.** Dice 만으로는 제품/인허가 언어와 접점이 없다. JBS-01K 보도치(민감도, DSC)와 같은 축을 쓰면 대화가 된다.

**P1 — 여력 되면**
4. 병인 분류를 **클래스 불균형 + 다중 클래스 지표(macro-F1, per-class recall)** 로 보고. Cryptogenic 처리 방침(제외/Others 병합)을 명시.
5. 추론 시간(케이스당 초) 측정 1줄 보고.
6. 사이트/스캐너 정보가 participants.tsv 에 있으면 **site-holdout 일반화** 실험 (A2 와 협의).

**P2 — 하지 말 것 / 문서로만 언급**
7. CT 모달리티 확장, PACS 연동, 풀 MLOps 는 개인 프로젝트 범위를 넘고 완성도만 떨어뜨린다. README 의 "한계 및 향후" 절에 **의도적으로 제외했다고 명시**하는 편이 낫다.
8. 인허가 문서 모사(임상성능시험 계획서 흉내)는 **권장하지 않음** — 허위성 오해 소지. 대신 "성능 보고 형식을 인허가 관례에 맞췄다" 수준으로만.

- **채용 담당자 오독 위험 평가**:
  - "실패한 프로젝트"로 읽힐 위험 — **중간 → 낮음**. 근거: 분할은 사전 등록 4개 기준 **전부 PASS**(Dice 0.6877, ICC 0.9839)이고, 병인 실패는 **주 지표 1개의 판정 불가**다. 30초 요약에 이 대비를 넣어 완화했다. 추가로 한계 5 의 "E1 PASS 규칙의 검정력은 애초에 0.54" 는 **결과 표 근처로 옮기면** 더 좋다(아래 (c) R3).
  - "방법론이 정직한 지원자"로 읽힐 가능성 — **높다**. 의료 AI 연구직에서 *사전 등록 → 1회 평가 → 음성 결과 보고* 를 완주한 개인 프로젝트는 드물다. 특히 **자기 성공 기준을 스스로 폐기하고 기록을 남긴 것**(A6)과 **CI 가 0 을 포함한다는 사실을 스스로 적는 것**(이번 보완)은 면접에서 그대로 질문거리가 되는 자산이다.

#### 4. A1 P0 3건의 처리 — **모두 정확히 반영됨(3번째는 이번에 명확화)**

| A1 의 P0 | 최종 처리 | README·헌장 반영 | 판정 |
|---|---|---|---|
| **DICOM I/O** | Astra 반박 수용 → **강등**. 헌장 "선택 확장" 3번에 "README 한 줄로 제외 이유 명시" 로 기록 | **README 에 그 한 줄이 없었다** → `## 의도적으로 하지 않은 것` 절 신설로 해결 | ✅ (보완함) |
| **2.5D/3D** | Astra 부분동의 → **P1**, 미실행 | 위 절에 "P1 로 강등, 2D 한 모델을 끝까지 검증하는 쪽을 택했다" 로 명시 | ✅ (보완함) |
| **민감도·특이도** | 민감도는 `metrics.py` 반영. **특이도는 Astra 반박으로 "계산 불가"** — A2 가 `acuteischaemicstroke` 관측값이 전부 1임을 독립 확인, `metrics.py` 는 NaN 출력 | README 에 **3곳**(에이전트 표 A1 행, 분할 표 아래 인용부, 새 제외 절)에서 "음성 환자 0명 → **계산 자체가 불가능**" 으로 서술. `eval_test.json` 의 `detection_specificity: NaN` 과 `detection_confusion {fp:0, tn:0}` 이 이를 뒷받침 | ✅ **명확하다** |

> 특히 특이도 항목은 "보고를 생략했다"가 아니라 **"정의가 성립하지 않는다"** 로 일관되게 서술돼 있어, 평가자가 "왜 특이도가 없나"를 물을 여지를 남기지 않는다. 이는 A1 의 최초 제안이 반박당한 결과이므로, 그 반박 과정을 README 에 남긴 것(에이전트 표 Astra 행 + 새 반박 목록)이 오히려 강점으로 작동한다.

#### 5. JLK 지원 맥락에서 30초 훑기에 놓치던 강점 — **4개를 표면으로 끌어올렸다**

1. **에이전트들이 서로의 오류를 잡아낸 과정 자체**(지적한 대로 이것이 최대 강점인데, 10행짜리 표에 묻혀 있었다) → 에이전트 절 앞에 **상호 반박 4건**을 불릿으로 명시(Astra→A1 특이도, A2→A6 기준 폐기, A3→A4 클립, A5a→A5b 17건 판정).
2. **재현성 실측**(다른 GPU 2장에서 `best.pt` sha256 바이트 동일, val Dice 16자리 일치) — `findings_log.md` 에만 있었다 → 빠른 시작 절에 추가. 연구직 평가자가 가장 빨리 신뢰하는 종류의 증거다.
3. **비용**(40 epoch 전체 학습 **279 초**) — "개인 장비로 끝까지 돌린 프로젝트"라는 인상을 준다.
4. **사전 등록 → 1회 평가 → 사후 무변경**이 30초 안에 보이도록 헤더에 원칙 문장을 배치.

아직 표면에 없는 것(선택): 외부 모델(Codex)이 `metrics.py` 를 **NumPy 로 독립 재구현해 1e-10 일치**를 확인한 사실. 지표 신뢰성의 강력한 증거지만 요약이 길어져 표에만 두었다.

#### 6. 구조·가독성 — **재배열함**

- **변경 전**: 헤더 → 무엇을 하는가 → **에이전트 표(10행 고밀도)** → 결과 → 한계 → 빠른 시작. 30초 훑는 사람이 **결과에 닿기 전에 가장 무거운 표**를 만난다.
- **변경 후**: 헤더 + **30초 요약** → 무엇을 하는가 → **결과 → 한계** → 에이전트 구성(+상호 반박) → **의도적으로 하지 않은 것** → 빠른 시작 → 구조 → 출처.
- 이제 **30초 훑기**는 헤더 4줄 + 요약 4불릿으로 끝나고, **5분 정독**은 결과 표 → 한계 → 에이전트 반박 기록 순으로 이어진다. 표는 전부 6행 이하로 유지했다.
